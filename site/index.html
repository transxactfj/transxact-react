Payments made easy.
In your React app.

01 — How it works

Two legs. Your server in the middle.

The package covers the two parts of a payment that happen in the browser. Everything that needs a secret key stays on your Merchant backend.

PAY

Create and redirect

Ask your backend to create a Checkout Session, then send the Customer to its hosted page. Works with Next.js, Vite, Remix and any React 18+ DOM app.

RETURN

Ask, don’t assume

When the Customer comes back, your backend is asked what really happened. The return URL is only a hint, never proof of payment.

FULFIL

Trust the webhook

Fulfil orders from signed webhooks on your server. The page only shows the Customer the outcome.

1 · BrowserCustomer clicks Pay
2 · Your backendCreates the session with your key
3 · TransxactHosted page takes the payment
4 · BrowserBackend confirms the status
02 — Quickstart

Four pieces of code.

Point the SDK at your backend, add a button, show the result, and give your backend one route.

1 · Configure

Wrap your app once so the button and the Return page share the setup. Use URLs for a simple backend, or your own functions when it needs a different request shape.

The provider is optional: you can pass the same options to each hook or button instead.

import { TransxactProvider } from "@transxact/react";

export function App({ children }: { children: React.ReactNode }) {
    return (
        <TransxactProvider createSessionUrl="/api/checkout" retrieveSessionUrl="/api/checkout">
            {children}
        </TransxactProvider>
    );
}

2 · Pay button

Say what is bought. The amount is decided by your backend, where the Customer can’t edit it.

The button is disabled and aria-busy while it works, so repeat clicks are ignored.

import { CheckoutButton } from "@transxact/react";

export function Cart({ orderId }: { orderId: string }) {
    return (
        <CheckoutButton payload={{ orderId }}> {/* never an amount */}
            Pay with M-PAiSA or MyCash
        </CheckoutButton>
    );
}

3 · Return page

Polls your backend while the session is pending, then settles on succeeded, failed or cancelled.

state is what the hook is doing; session.status is the payment.

import { useCheckoutReturn } from "@transxact/react";

export function CheckoutReturn() {
    const { state, session, refresh } = useCheckoutReturn({ retrieveSessionUrl: "/api/checkout" });

    if (state === "error") return <button onClick={refresh}>Try again</button>;
    if (state !== "settled") return <p>Confirming your payment…</p>;
    return <p>{session?.status}</p>;
}

4 · Merchant backend

The one piece that runs on your server, not in the browser. It uses @transxact/node and your secret key.

It looks up the price, forwards the Idempotency-Key, and reports the status. A runnable version is in the example app. This one uses the Next.js App Router.

// app/api/checkout/route.ts — server-only
import { TransxactApiClient } from "@transxact/node";

const transxact = new TransxactApiClient({ token: process.env.TRANSXACT_SECRET_KEY! });

export async function POST(request: Request) {
    const { orderId } = await request.json();
    const order = await findOrder(orderId); // your own lookup
    const session = await transxact.checkoutSessions.create({
        idempotencyKey: request.headers.get("Idempotency-Key") ?? crypto.randomUUID(),
        amount: order.totalCents,
        currency: "FJD",
        successUrl: "https://shop.example/checkout/return",
        cancelUrl: "https://shop.example/checkout/return",
    });
    return Response.json({ hostedUrl: session.hostedUrl });
}

export async function GET(request: Request) {
    const id = new URL(request.url).searchParams.get("session_id")!;
    const session = await transxact.checkoutSessions.retrieve({ id });
    return Response.json({ status: session.status });
}
03 — Safety rules

Built so the unsafe thing can’t happen.

These rules are part of the SDK’s design and are covered by its tests.

No secret keys

The SDK has no key option and never calls Transxact. Every request goes to your Merchant backend.

No amounts

The browser says what is bought. Prices are decided on your Merchant backend.

Checked links only

The hosted URL must be https (or http on localhost for local development) before the Customer is sent there.

One key per attempt

A retry after a lost response replays the same Checkout Session, so no double charges.

No double clicks

The button is disabled while it creates a session and redirects. Repeat clicks are ignored.

Request errors aren’t payment failures

A failed lookup is state: "error"; a failed payment is status: "failed". They can’t be confused.

04 — API

Three exports and one error type.

Props on a hook or component always beat the provider. At the same level, a function beats a URL.

<TransxactProvider>

Optional defaults for everything beneath it.

TransxactReactError

Errors raised by the SDK carry a code. Errors thrown by your own functions pass through unchanged.

codeWhen
config_missingNeither props nor provider say how to reach your backend
http_errorA URL shorthand got a non-2xx response; error.status and error.body are set
invalid_responseThe response isn’t JSON, or has no valid hostedUrl or status
